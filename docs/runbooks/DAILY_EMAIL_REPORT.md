# 每日市场邮件日报维护说明

本文是每日 08:00 邮件日报与 Discord 同步日报的维护入口。任何日报标的、公式、信号、调度、配置或输出变化，都应与代码在同一个改动中同步更新本文。

## 1. 功能边界

- 调度时间：每天 `08:00`，时区由 `ALERT_TIMEZONE` 决定，默认 `Asia/Taipei`。
- 邮件：发送四市场合并完整版，同时包含纯文本和 HTML。
- Discord：发送与邮件纯文本完全相同的完整内容；超过单条消息限制时自动拆分为连续多段。
- A股章节是交易前瞻，分析最近一个已经完成的交易日。
- 只有出现了新完整日线的市场才会再次进入报告。休市市场不会重复使用旧日线。
- 报告使用确定性规则生成，不调用 LLM。
- 用户可见输出不显示数据供应商、监控计划、运行关系或内部错误堆栈。
- 本阶段没有日报预览页面或公开日报 HTTP API；SMTP 渠道可在“告警 → 通知渠道”中维护。

HTML邮件使用系统无衬线中文字体栈（优先苹方、微软雅黑），并统一采用方向语义色：

- 上涨趋势、看多动能、做多机会：绿色。
- 下跌趋势、看空动能、做空机会：红色。
- 趋势不明确、动能平衡、等待确认：琥珀色。

每个标的使用独立卡片展示，市场状态、动能变化和交易建议分别高亮。纯文本邮件不依赖颜色，必须保留完整方向文字。

主要实现：

- `backend/app/core/daily_report_analysis.py`：公式、热度聚合、机会过滤和渲染。
- `backend/app/core/daily_report_sources.py`：行情榜单、热榜、官方事件和缓存适配。
- `backend/app/core/daily_report_service.py`：市场编排、数据库、幂等和重试。
- `backend/app/core/daily_report_delivery.py`：SMTP 与 Discord 投递。
- `backend/app/tasks/alert_scheduler.py`：08:00 调度。
- `backend/app/tasks/daily_report_cli.py`：手动预览和发送。

## 2. 报告结构

邮件标题为 `每日市场日报｜YYYY-MM-DD`，正文依次为：

1. 加密货币
2. A股交易前瞻
3. 美股
4. 商品
5. 日线机会
6. 未来7日重点事件

各市场固定标的：

| 市场 | 固定标的 |
|---|---|
| 加密货币 | 比特币 `BTC-USD` |
| A股 | 上证指数 `000001.SS`、创业板指数 `399006.SZ`、科创50 `000688.SS` |
| 美股 | 纳斯达克综合指数 `^IXIC`、标普500 `^GSPC` |
| 商品 | 黄金 `GC=F`、白银 `SI=F`、WTI原油 `CL=F` |

A股和美股还分析成交额前五、全部股票类自选标的和热门前三。加密市场分析 BTC 和热门前三。商品不做热榜。

标的跨列表重合时只分析一次，标签合并且顺序稳定，例如：

```text
贵州茅台（600519.SS） [成交额前五/自选/热门]
```

A股热榜与成交榜仅保留沪深京普通A股；美股排除 ETF、基金、权证、优先股和单位证券；加密热榜排除稳定币、封装币及杠杆代币。

## 3. 统一分析公式

所有日线必须先通过 `completed_daily_candles()` 的闭合判断。统一拉取 180 根，分析至少需要2根，完整判断趋势至少需要122根。

- 涨跌幅：`(close / previous_close - 1) × 100%`
- 波动区间：`low–high`
- 振幅：`(high - low) / previous_close × 100%`
- 成交量变化：`(volume / previous_volume - 1) × 100%`
- 均线：简单移动平均 `MA20 / MA60 / MA120`
- 均线位置内部使用 `(close - MA) / ATR14` 标准化，绝对值不超过 `0.10 ATR` 时显示“价格位于均线附近”。
- 均线斜率使用 `(MA[t] - MA[t-2]) / ATR14`，高于 `0.05` 为向上、低于 `-0.05` 为向下，其余为基本走平。

指数原生成交量缺失或不可靠时，成交量显示“不适用”，不使用 ETF 代理。

邮件不得展示 MA 的具体数值或距离百分比，只输出价格与 MA 的关系及 MA 斜率。市场主状态只保留三种，数据不足不属于市场状态：

- 上涨趋势：满足中长期多头结构，或者价格在三条均线上方且三条均线全部向上。若进一步满足 `close > MA20 > MA60 > MA120` 且三条均线均向上，文案使用“强劲上涨趋势”。
- 下跌趋势：满足中长期空头结构，或者价格在三条均线下方且三条均线全部向下。若进一步满足 `close < MA20 < MA60 < MA120` 且三条均线均向下，文案使用“强劲下跌趋势”。严格均线排序不得作为普通下跌趋势的必要条件。
- 趋势不明确：不满足上述条件，统一涵盖原来的震荡、过渡和均线纠缠。
- 数据不足：不足122根完整日线或任一长周期均线不可用，不给方向性交易建议。

回调和反弹不是新的市场状态，只作为战术阶段：

- 上涨趋势中价格不在 MA20 上方或 MA20 转下：`pullback`。
- 下跌趋势中价格不在 MA20 下方或 MA20 转上：`rebound`。
- 其他明确趋势：`continuation`。

每个标的在价格、成交量之后固定输出“市场状态、均线结构、动能变化、交易建议、风险关注”。上涨趋势禁止逆势做空，已有多头继续持有，未持仓等待回调并重新转强；下跌趋势禁止逆势抄底，可做空品种等待反弹承压，不能做空的现货减仓或观望；趋势不明确时降低仓位并等待方向确认。

“2个交易日前”在升序数组中对应 `[-3]`，不是两个自然日。修改窗口或 ATR 阈值时必须同步更新单元测试和本文。

### 日线 MACD 动能

日报使用标准 `MACD(12,26,9)`，并以 ATR14 标准化柱体和柱体变化：

```text
hist_norm = HIST / ATR14
delta_norm = (HIST[t] - HIST[t-1]) / ATR14
```

- 正柱且继续扩大：上涨动能增强。
- 正柱但缩短：上涨动能减弱。
- 负柱且继续扩大：下跌动能增强。
- 负柱但缩短：下跌动能减弱。
- 柱体绝对值不超过 `0.02 ATR`：多空动能接近平衡。
- 单日变化绝对值不超过 `0.01 ATR`：动能大致稳定。

某一同号柱体段至少连续增强2日后首次缩短时，邮件直接写“上涨动能首次衰减”或“下跌动能首次衰减”，并根据当前 MA 主状态补充交易关注结论。该描述不计算星级、不进入日报机会模块；只有已经确认的 MACD 背离仍可进入机会模块。

## 4. 热门产品

热度窗口是最近3个自然日。每天保存当前公开热榜快照到 `hot_product_snapshots`，再对窗口内同一标的聚合。

综合热度：

```text
heat_score = average_attention_score × 70%
           + turnover_percentile × 30%
```

- `attention_score`：公开搜索、访问或讨论热榜名次归一化到 `[0, 1]`。
- `turnover_percentile`：标的窗口内平均成交额在本次候选集合中的百分位。
- 结果按综合热度降序，每个市场取3个。
- 当前上游失败时，适配层先使用72小时内磁盘缓存；数据库中最近3日快照仍可继续聚合。
- 没有关注热榜但有交易数据时，可将注意力分数视为0并按交易活跃度降级。

运行时磁盘缓存位于：

```text
data/market/daily_report_cache/
```

磁盘缓存只用于上游短暂故障，不允许把旧行情标记为新的交易日。用户可见正文不会展示来源名称。

## 5. 成交额榜与自选股

- A股：全市场快照的原生成交额降序取前五。
- 上证指数、创业板指数和科创50的日线依次尝试 AKShare Sina、AKShare Tencent、Yahoo，最近一次成功的指数日线缓存7天作为上游故障回退。
- 美股：免费全市场股票快照中按 `last_price × volume` 计算估算成交额并取前五。
- 自选股从 `watchlists` 读取，只接受 `stock` 或 `equity` 类型。
- `.SS/.SZ/.BJ` 或六位A股代码进入A股；没有其他市场后缀、不是加密或期货格式的股票进入美股。

某只股票同时属于成交额前五、自选和热门时，`_merge_specs()` 负责合并标签及机会资格。

## 6. 日线机会

机会池：

- 加密：BTC 与热门前三去重并集。
- A股：成交额前五、自选、热门前三去重并集。
- 美股：成交额前五、自选、热门前三去重并集。
- 指数和商品当前不进入机会池。

只保留完整日线上的两种事件：

1. `ma_breakout`：MA20、MA60 或 MA120 的 ATR 归一化有效突破。
2. `macd_divergence_confirmed`：MACD 顶背离或底背离确认。

以下事件即使底层检测器返回，也必须被日报过滤：

- `ma_retest`
- `trendline_breakout`
- `convergence_breakout`
- `macd_momentum_observation`

`macd_momentum_observation` 虽不进入机会模块，但其中的首次动能衰减会作为无星级的日常状态写入对应标的分析。机会星级继续使用 `signal_strength.py`。日线 MA 突破和日线 MACD 背离确认当前均为五星。星级代表注意优先级，不代表胜率或仓位。

邮件和 Discord 都展示全部有效机会并按星级降序。

## 7. 宏观与财报

窗口为报告日期起未来7个自然日，不包含第8天。

- FOMC：读取美联储会议日历，以会议最后一天美东14:00为决议时间，再换算到报告时区。
- CPI、非农：读取 BLS 官方 iCalendar；只保留 `Consumer Price Index` 与 `Employment Situation`。
- 财报：固定查询 `AAPL、MSFT、GOOGL、AMZN、NVDA、META、TSLA`。
- 只能确认财报日期时显示“时间待确认”，不猜盘前盘后。
- 官方日历成功读取后会写入磁盘缓存；短暂无法访问时允许使用14天内缓存。
- 没有事件时显示“未来7日无重点事件”。

旧的 `economic_calendar.py` 仍可能被其他接口引用，但日报不得调用其中的硬编码 FOMC 日期或按星期推算逻辑。

## 8. 调度、完整日线与幂等

APScheduler 可用时注册 `daily_market_report` cron；不可用时，内置分钟循环在目标时间后执行一次。

日报表 `daily_reports` 以 `(report_date, timezone)` 唯一：

- 同一天重复触发只读取已有记录并重试失败渠道。
- `market_dates` 保存每个已成功市场使用的最后交易日。
- 下一份报告若发现市场最后交易日未变化，则跳过该市场。
- 加密市场每天都会产生新日线，因此正常情况下每天至少有加密章节。

投递状态按渠道独立保存：

- `pending`
- `sent`
- `failed`
- `disabled`

邮件成功、Discord 失败时只重试 Discord。每个失败渠道最多尝试6次。未配置渠道标记为 `disabled`，不会持续报错；后续补齐配置并再次触发时，`disabled` 会恢复为 `pending` 并尝试发送。邮件优先使用数据库中启用的 Email 渠道（默认渠道优先），不存在时回退到 SMTP 环境变量。Discord 优先读取 `DISCORD_WEBHOOK_URL`；环境变量为空时复用数据库中启用的 Discord 通道。

某市场无法获取完整日线时，章节显示“数据暂不可用”，其他市场继续生成和发送。内部错误仅保存在结构化负载和日志。

## 9. Email 通知渠道与环境变量

推荐在前端“告警 → 通知渠道 → 添加渠道 → Email”中配置：

- 常见公共邮箱（Gmail、Outlook、QQ、163、126、Yahoo、iCloud、Zoho 等）只需先输入邮箱号，系统会按域名自动填写 SMTP 主机、端口和加密方式，并默认使用该邮箱作为 SMTP 用户名、发件人和收件人。
- SMTP 密码仍需输入；Gmail、QQ、163 等通常应使用应用专用密码或授权码，而不是网页登录密码。
- 自定义企业邮箱无法识别时，继续手动填写 SMTP 主机、端口、加密方式、用户名、发件人和收件人；收件人支持多个英文逗号分隔的地址。

保存后应先点击“测试”。编辑渠道时密码不会回显，留空表示保留原密码。查询接口只返回非机密连接参数和“是否已保存密码”，不会返回 SMTP 密码。渠道凭据保存在服务器数据库的 `notification_channels.config`；部署方应限制数据库访问和备份权限。

如果只配置了 `.env` 中的 SMTP 环境变量，前端也会显示一条“环境变量 Email（日报回退）”只读渠道，并提供“测试邮件”按钮；该配置不会写入数据库，也不能在页面中编辑。数据库 Email 渠道则可编辑、启停，并可被监控计划引用。

没有前端 Email 渠道时，以下环境变量继续作为兼容回退：

```dotenv
DAILY_REPORT_ENABLED=true
DAILY_REPORT_HOUR=8
DAILY_REPORT_MINUTE=0
ALERT_TIMEZONE=Asia/Taipei

SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USERNAME=
SMTP_PASSWORD=
SMTP_USE_TLS=true
SMTP_USE_SSL=false
REPORT_EMAIL_FROM=market@example.com
REPORT_EMAIL_TO=one@example.com,two@example.com

DISCORD_WEBHOOK_URL=
```

规则：

- `SMTP_USE_TLS` 和 `SMTP_USE_SSL` 不得同时为 `true`。
- STARTTLS 常用端口587；隐式 SSL 常用端口465。
- 只有 `SMTP_HOST`、`REPORT_EMAIL_FROM`、`REPORT_EMAIL_TO` 都存在时，邮件渠道才视为已配置。
- 使用环境变量时，密码只放 `.env` 或部署环境，不写入仓库。

## 10. 手动预览与排查

在 `backend/` 目录执行：

```bash
python -m app.tasks.daily_report_cli --dry-run
python -m app.tasks.daily_report_cli --date 2026-07-24 --dry-run --html /tmp/daily-report.html
python -m app.tasks.daily_report_cli --send
```

- 默认行为等同 `--dry-run`，不写日报记录、不投递。
- `--date` 用于历史日期版式和日线检查；免费上游不提供历史热榜，因此热榜仅供版式参考，且历史日期不能与 `--send` 同时使用。
- `--send` 会持久化并真实投递，受同日幂等键保护。

常见问题：

1. **邮件显示 disabled**：检查 SMTP 三个必填项和收件人列表。
2. **只有部分市场**：检查 `market_dates`；休市或没有新完整日线属于正常行为。
3. **热门榜为空**：检查网络、AKShare版本以及 `data/market/daily_report_cache`；不影响固定标的。
4. **A股名称或代码异常**：确认六位代码后缀映射，6开头为 `.SS`，0/3为 `.SZ`，4/8为 `.BJ`。
5. **重复邮件**：检查数据库唯一约束是否存在，不要绕过 `generate_and_deliver_daily_report()` 直接发送。
6. **官方事件为空**：检查 BLS/Fed 可访问性及14日缓存；禁止恢复为日期猜测。

## 11. 测试和扩展要求

运行：

```bash
cd backend
pytest -q
```

修改日报时至少覆盖：

- 公式和2交易日均线斜率。
- 上涨趋势、下跌趋势、趋势不明确、数据不足，以及趋势内的回调/反弹战术状态。
- 邮件不展示 MA 数值或距离百分比，MACD 首次衰减不带星级且不进入机会模块。
- 3日热度70/30聚合。
- 标签去重。
- 机会白名单，确保回踩、结构和一星观察不会进入日报。
- 指数成交量不适用。
- HTML/文本/Discord不出现数据来源和运行过程。
- 单市场失败、分渠道失败及同日幂等。

增加新市场时，需要同时补充：

1. `MARKETS` 固定标的及市场时区。
2. `completed_daily_candles()` 的准确收盘规则。
3. 成交额和热榜适配器。
4. 自选股市场归属规则。
5. 邮件、Discord和失败场景测试。
6. 本文对应章节。
